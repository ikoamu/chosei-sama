# 調整条件は UI で構造化せず、LLM が自然文から解釈する

参加者ピッカーは**参加者解決とフリーテキスト（希望条件）の受け渡し**だけを行い、所要時間・検索期間・単発/定期・頻度・回数・希望時間帯といった**調整条件の抽出はすべて Agent（LLM＋システムプロンプト＋zod ツールスキーマ）が自然文から解釈**する。当初は単発/定期のセグメントトグルと種別シグナルを送信文に含めていた（`be7279d`）が、二択 UI が「単発の複数回」等を表現できずフォーム項目も増えるため撤去し、フリーテキスト＋LLM 推測へ寄せた（`58747e0`）。

## Considered Options

- **UI で構造化（撤回）**: 種別トグルや所要時間・期間の入力欄を UI に置き、構造化シグナルを Agent に渡す。決定的で聞き返しが減る一方、表現の幅が UI に縛られ（「何回か」「隔週6回」等が二択に収まらない）、入力項目と操作が増える。
- **LLM が自然文から解釈（採用）**: 入力口はフリーテキスト1本。表現の多様性に強く操作も最小。ただし出力は決定的でなく、必須条件の欠落時の挙動を別途定める必要がある。

## Consequences

- 同じ依頼でも抽出結果が揺れうる（非決定的）。再現性は zod スキーマ（必須/型/範囲）と、欠落時の聞き返しで担保する。
- 欠落時の補完ルール（プロンプトに明文化する）:
  - **所要時間**が欠ければ聞き返す。**検索期間**が欠ければ既定（今日〜2週間後）で補完する。
  - 既定は**単発**。`隔週`/`毎週`/`定例` 等の明示的な繰り返し語があるときだけ**定期**に倒し、曖昧なら聞き返す。
  - 定期の**頻度**未指定は毎週（everyNWeeks=1）を既定、**回数**が欠ければ聞き返す。
- **希望時間帯はソフト**（ランキングを上げるだけで候補は絞らない）。「午後だけ」のようなハード制約には昇格させない。ハードな枠は別概念の勤務時間（既定 9–18）が担う。
- 参加者だけは例外で、UI（ピッカー）でも自然文（findPeople）でも解決できる。どちらも同じ `参加者解決`。
