# チャットをやめ、Jev が下書きした調整条件をフォームで確定する

チャットエージェント（汎用 LLM＋ツール呼び出し）をやめ、「依頼の自然文 → TypeSafe AI の Jev が**調整条件の下書き**（項目ごとに確からしさ付き）を返す → 編集可能なフォームでユーザーが確定 → 決定的なコードで候補を出す → 承認して予約確定」という流れに作り替える。ADR 0002 が抱えていた「抽出が非決定的で、欠落時の聞き返しをプロンプトの言葉で担保している」弱点を、型と確からしさの閾値に置き換えるため。本 ADR は ADR 0002 を置き換える。

チャットをやめるのに合わせ、Durable Object（`ChatAgent`）と Agents SDK も捨て、セッション Cookie を都度検証する**状態を持たない Worker の HTTP API**（下書き生成・候補提案・予約確定）にする。`refresh_token` はもともとセッション Cookie にあり、DO が担っていたのは会話の状態だけだったため。予約確定の承認は「人がボタンを押して予約確定 API を呼ぶこと」そのものになる。ユーザーごとの状態（下書きの保存・通知など）が必要になったら、そのとき改めて DO を検討する。

## Consequences

- Jev は社外のアーリーアクセスのベンダーなので、送るのは**条件欄の文章（メールアドレスらしき文字列は伏せる）と今日の日付・タイムゾーンだけ**にする。参加者・FreeBusy の結果・候補は送らない。利用前に TypeSafe の規約（学習への利用・保持期間）を確認する。
- Jev が失敗したら空の下書きを返し、全項目を要確認にして手入力させる。Jev がなくても全機能が使える。

## Considered Options

- **フォームのみ（不採用）**: ADR 0002 で撤回した理由（表現の幅が UI に縛られる・入力項目が増える）がそのまま再発する。
- **フリーテキストのみで Jev の判断を即実行（不採用）**: 修正手段が「言い直し」しかなく、誤判断の訂正が重い。
- **自然文を入口に、Jev がフォームを下書き（採用）**: 入口は自然文のまま（表現の幅を保つ）、普段は下書きを確認するだけ（操作が増えない）。要確認項目のハイライトが聞き返しの代わりになる。
